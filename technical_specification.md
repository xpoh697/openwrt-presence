# Техническое задание (ТЗ): OpenWrt Mesh Presence Tracking для Home Assistant (HACS)

## 1. Введение и цель проекта
Разработка специализированной интеграции для Home Assistant (распространяемой через HACS) для высокоточного отслеживания присутствия устройств (Presence Detection) и определения их конкретного местоположения в Mesh-сети из 3-х точек доступа под управлением OpenWrt (версия 25+) с установленным LuCI.

Ключевая особенность решения:
- **Zero-Touch на роутерах**: на сами роутеры не требуется компилировать и устанавливать сторонние пакеты или скрипты. Используется штатный API LuCI / ubus JSON-RPC, уже встроенный в OpenWrt.
- **Централизованное управление в Home Assistant**: все белые списки устройств, привязка к комнатам и параметры роуминга настраиваются в едином UI Home Assistant.

## 2. Архитектура системы

### 2.1. Аппаратное и системное окружение
- **Роутеры OpenWrt**: 3 устройства с OpenWrt 25+ и штатным LuCI (uhttpd + rpcd).
  - Узел 1 (например, Master/Main Router).
  - Узел 2 (Mesh AP 1).
  - Узел 3 (Mesh AP 2).
- **Home Assistant**: Home Assistant OS / Container / Supervised с установленным HACS.
- **Связь**: Локальная сеть (LAN), протокол HTTP/HTTPS ubus JSON-RPC.

### 2.2. Компоненты системы
1. **Штатный OpenWrt LuCI / ubus API**:
   - Предоставляет методы `ubus call iwinfo assoclist` и `ubus call hostapd.* get_clients`.
   - Сессионный доступ через `rpcd` (токен авторизации `ubus_rpc_session`).
2. **Интеграция Home Assistant (HACS `openwrt_mesh_presence`)**:
   - **Async ubus RPC Client**: Асинхронный клиент с поддержкой батчинга запросов ко всем радиоинтерфейсам роутера и переиспользованием сессий.
   - **Mesh Presence Coordinator**: Опрашивает 3 роутера параллельно, агрегирует подключенных клиентов, определяет, к какой конкретно AP подключен каждый клиент, отслеживает уровень сигнала (RSSI).
   - **Roaming State Machine (Anti-Flapping)**: Сглаживание при переключении между узлами (grace period 10-15 сек). Предотвращает ложный переход в `not_home` при смене точки доступа.
   - **UI Config & Options Flow**:
     - Мастер добавления узлов сети (IP, порт, учетные данные).
     - Выбор режима отслеживания (только выбранные MAC / все устройства).
     - Привязка точек доступа к зонам/комнатам (например, AP1 -> Зал, AP2 -> Спальня, AP3 -> Кухня).

## 3. Требования к сущностям в Home Assistant

На каждое отслеживаемое устройство создаются:
1. `device_tracker.<device>`: Состояние `home` / `not_home`.
2. `sensor.<device>_connected_ap`: Имя текущей подключенной точки доступа (например, «Зал», «Спальня»).
3. `sensor.<device>_rssi`: Уровень сигнала в dBm (с атрибутами качества связи, шума и скорости передачи).
4. `sensor.<device>_last_seen`: Временная метка последнего подтверждения присутствия.

Диагностические сенсоры для каждого из 3-х роутеров:
- `binary_sensor.<ap_name>_status`: Доступность самого роутера (Online/Offline).
- `sensor.<ap_name>_clients_count`: Количество активных беспроводных клиентов на точке.

## 4. Нефункциональные требования
- **Отказоустойчивость**: Если один из трех роутеров выключен, опрос остальных двух продолжается без задержек.
- **Безопасность**: Шифрование учетных данных в хранилище конфигураций HA, поддержка HTTPS/SSL при наличии сертификатов на LuCI.
- **Производительность**: Использование пакетных запросов (JSON-RPC batching) для минимальной нагрузки на CPU роутеров (< 0.1%).
